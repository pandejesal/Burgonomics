## Cross-service invariants

- Client UI, branch ownership and brand ownership do not create financial authority. Server validates current catalog/outlet/mode/quantity/options, amounts in paise/INR, tax/fees/discount/rewards, capture identity and permitted transitions.
- Distinct facts: created order, priced order, external cash collection, gateway capture, POS transport acceptance, restaurant acceptance, physical/displayed KOT, dispatch booking and completion. One boolean `synced` cannot stand in for all of them.
- Persist intent/attempt identity and a request fingerprint **before** irreversible external work. Keep returned receipts/ambiguity until reconciled. Firestore transaction retries must not themselves repeat a provider side effect.
- Vendor support for idempotency/status lookup must be contract-backed. A locally deterministic key cannot promise the vendor deduplicates. No external exactly-once claim from local locks alone.
- Missing credentials/config/mapping fails closed. Test fixtures remain local/test-only; release bundles must not expose seeded operational data or simulated rider/payment success. Existing guards must be tested, not deleted because a source file contains a mock branch.
